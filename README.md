## 문제

체계적인 인수인계 프로세스는 대기업 정도 되어야 갖추고 있는 경우가 많다. 하지만 실제로 인수인계가 급하게, 부실하게 이뤄지는 곳은 오히려 그 반대다 — 군대의 보직 교대, 소규모 스타트업의 담당자 교체, 아르바이트생의 퇴사와 신규 채용까지. 이런 조직들은 대부분 "일을 몸으로 익힌 사람"만 있고, 그 지식을 문서로 옮기는 절차 자체가 없다.

문제의 본질은 의지가 아니라 방법이다. 대부분의 사람은 자기 업무를 처음부터 조리 있게 설명하는 데 익숙하지 않다. 어디서부터 말해야 할지 몰라서 결국 "그냥 옆에서 보고 배워"로 끝난다.

## 무엇을 만들었는가

사용자가 자기 업무를 편하게 말로 설명하면, AI가 빠진 부분(순서, 예외, 이유)을 되물어가며 대화를 이끌고, 대화가 끝나면 다음 사람이 바로 실행할 수 있는 체크리스트 문서로 자동 정리해주는 웹 서비스.

문서화 능력이나 시간 여유가 없는 조직 — 군대, 소규모 팀, 아르바이트 현장까지 — 어디에나 적용 가능하도록 설계했다.

## 핵심 기능

- **Google 로그인** — 본인 문서만 안전하게 관리
- **맞춤형 AI 인터뷰** — 업무 주제를 입력하면 그에 맞는 질문으로 시작, 답변에 따라 후속 질문을 동적으로 생성
- **자동 문서화** — 대화를 체크리스트 형태의 문서로 자동 재구성
- **비개발자 친화적 수정** — 마크다운 문법 없이, 제목/개요/순서/주의사항을 항목 단위로 수정 가능한 구조화 편집기
- **공유 & 인쇄** — 링크로 공유하거나, 문서 전용 레이아웃(작성자·문서ID·열람일 포함)으로 인쇄/PDF 저장
- **주제별 필터·검색** — 여러 업무의 인수인계 문서를 주제 태그로 구분해 관리
- **문서 삭제/관리** — 확인 절차를 거친 안전한 삭제

## 기술 스택

- **Framework**: Next.js (App Router)
- **DB / Auth**: Supabase (PostgreSQL, Row Level Security, Google OAuth)
- **AI**: Google Gemini API
- **배포**: Netlify
- **개발 환경**: GitHub Codespaces (개인 노트북 없이 브라우저에서 전 과정 개발)

## 아키텍처 & 보안 설계

- 모든 문서·세션 테이블은 Row Level Security로 **본인 소유 데이터만 조회/수정 가능**하도록 DB 레벨에서 강제
- 공유 링크는 slug 기반의 `SECURITY DEFINER` 함수로만 접근 가능 — 테이블 자체를 공개 API에 노출하지 않고, 딱 필요한 필드만 반환
- API 엔드포인트는 Supabase 세션 토큰을 서버에서 검증한 뒤에만 동작 (로그인 화면만 가리는 방식이 아님)
- 시간당 문서 생성 횟수에 속도 제한(rate limit)을 걸어, 무료 API 한도 남용과 어뷰징을 함께 방지
- 인쇄/PDF본에는 작성자·문서ID·열람 시각을 자동 삽입해, 외부 유출 시 최소한의 추적 가능성 확보

## 개발 과정: 트러블슈팅 로그

실제 개발 중 부딪힌 문제와 대응 과정을 정리한다. 완성된 결과물만으로는 보이지 않는 부분이라 남겨둔다.

**API 공급자 전환**
초기엔 Claude API로 설계했으나, 무료 티어 제약으로 Google Gemini API로 전환. 개발 도중 사용하던 모델이 지원 종료(404)되고, 대체 모델이 일시적 과부하(503)를 일으키는 상황을 겪으며 모델 버전에 의존하지 않는 재시도 로직을 추가했다.

**Git 저장소 분리 사고**
배포 플랫폼 연동 과정에서 원격 저장소가 의도치 않게 별개의 빈 레포로 분리되어, 로컬에 쌓아둔 커밋 히스토리가 반영되지 않는 문제가 발생했다. 원인을 `git remote -v`로 진단하고, 강제 push로 정상 저장소에 이력을 복구했다.

**환경변수 관리 실수**
클라우드 개발 환경(Codespaces)을 새로 열 때마다 `.env.local`이 초기화되는 걸 반복적으로 놓쳤고, `echo` 명령어 자체가 파일 내용으로 잘못 저장되는 실수도 겪었다. 환경변수 검증을 배포 전 체크리스트에 포함시키는 습관으로 이어졌다.

**배포 플랫폼 이관**
Vercel에서 Netlify로 재배포하는 과정에서, Next.js 빌드 캐시 파일에 서버 전용 API 키 값이 일시적으로 기록되는 것을 Netlify의 시크릿 스캐너가 유출로 오탐하는 이슈를 만났다. 실제 소스 코드(`git grep`)에는 값이 없는 것을 확인해 오탐임을 검증한 뒤, 스캔 예외 경로를 지정해 해결했다.

**OAuth 리다이렉트 관리**
개발 환경 주소가 세션마다 바뀌는 특성 때문에 Google OAuth 리다이렉트 URI를 반복적으로 재설정해야 했고, 이 경험이 배포 주소를 고정하는 것의 실질적인 가치를 체감하게 했다.

## 알려진 한계

- **PDF/캡처 유출 방지**: 화면 밖으로 나간 문서의 무단 배포는 기술적으로 완전히 차단할 수 없다. 워터마킹으로 추적성만 확보하는 정도가 현실적인 대응이다.
- **대규모 트래픽/공격 방어**: 애플리케이션 레벨의 속도 제한 외의 방어는 Vercel/Netlify, Supabase의 플랫폼 레벨 보호에 의존한다. 조직 단위로 정식 도입할 경우 별도의 인프라 검토가 필요하다.
- **폐쇄망 환경**: 국방망처럼 외부 인터넷 접근이 제한된 환경에서는 현재 구조 그대로 적용할 수 없으며, 내부 인프라로의 이식이 별도로 필요하다.

## 로드맵 & 확장 아이디어

- **협업 도구 연동**: 생성된 문서를 Notion 페이지나 Slack 채널로 바로 내보내는 연동
- **리마인더**: 인수인계 검토/갱신 기한이 다가오면 알림을 보내는 기능
- **조직 단위 문서함**: 개인 계정을 넘어, 팀/부서 단위로 문서를 공유하고 관리하는 구조
- **다국어 지원**: 생성된 문서를 다른 언어로 자동 번역
- **캡처 확장 프로그램**: 업무 중 떠오른 메모를 브라우저 확장으로 바로 기록해두었다가, 인터뷰 시 맥락으로 활용
